## How the media was accessed (Spatial MCP workaround)

- `get_space({id, itemId:<nested id>})` and `get_video_frames({id, itemId:<nested id>})` fail with "Unknown item id": the item lookup does not reach inside folders.
- `get_space({id, itemId:<folder id>, includeMedia:true, maxOutputTokens:500000})` puts images inline in the response (items 1–4 via `mediaBlockIndex`). It stops at 4 media blocks per response, whatever `maxOutputTokens` is set to.
- The rest were read straight from the app's local files: images are at `~/Library/Containers/com.44x.spatial/Data/Library/Application Support/Originals/<itemId>.png`, videos at `.../Data/tmp/<itemId>.mp4` (the `videoPath` given in the folder response). Video frames were pulled with ffmpeg as a 12-frame grid plus full-resolution stills.

## Workspace tabs (confirmed in B6BD5981 and 789CB4EF)

- Tabs live in the title bar to the right of the traffic lights and navigation buttons. Each tab is about 28px tall and up to ~170px wide, with an icon/glyph, a truncated title and a × that shows only on the active or hovered tab. The active tab is a filled pill one step lighter than the chrome. Then come + and an overflow ⌄ that lists every tab.
- Tab kinds: project, task (run), doc and review/tour. The glyph shows the kind or the agent.
- Behaviour: ⌘T new, ⌘W close, ⇧⌘T reopen the last closed tab (keep a stack), ⌘1–9 jump to a tab, ctrl-tab cycles. Clicking a sidebar item replaces the current tab; ⌘-click opens it in a new tab. Switching tabs is instant with no slide. Opening a new tab fades and expands its width (~150ms).
- Persistence: store the open tabs, their order, the active tab and the closed stack per workspace in the Bun SQLite service so they survive a restart.
- The bottom terminal/log drawer has its own set of tabs.

## Design tokens (derived)

- Dark: page #0B0B0B–#121212, panels #1A1A1A, raised #222/#2A2A2A, borders #2A2A2A–#333, text #EDEDED, secondary #8A8A8A, tertiary #5C5C5C.
- Light: page #FAFAFA, sidebar #EEEEEE, card #FFF, border #E6E6E6, tray #F4F4F4.
- Status colours: blue #3B82F6 (running/active), amber #F59E0B (needs you / approval), green #22C55E (ready/passed/+), red #EF4444 (failed/−), pink #EC4899 (validating), teal heatmap ramp.
- Fonts: Inter-like sans; body text 13px (dense lists) / 15–16px (chat and docs); section labels 12px secondary; numbers use tabular figures; code in a monospace face at 12–13px.
- Radii: 6 (chips), 8 (rows, tabs, buttons), 10–12 (cards), 16 (popover tray). Nested radii follow outer = inner + padding.
- Spacing: 4px grid; rows 28–32px in sidebars and 60px in card lists; card padding 12–16px.
- Motion: panels ~220ms ease-out; card height ~200ms; list item enter: fade + 4px rise over 150ms; spinners rotate continuously; respect reduced motion (opacity only).

## Product mapping

- Shell = V1. Home/Stats = #2 plus #1. Board = #5, with #6's gates and intervention styling. List and task drawer = #4 with the #9/#10 status icons. Run view = #7 inspector plus V2 timeline. Diffs = V1 right pane. Loading states = #8. Buttons = #3.
- Projects: the sidebar tree uses #5 badges as source markers (standalone/GitHub/Linear) in place of Cloud/MacBook.
- Data: all client CRUD (projects, tasks, workflows, agents, instructions, skills, VM configs, docs, tabs) goes against the Bun SQLite service. Scheduler, harness and VM execution only fill in the scaffolded live fields (status, timers).

## Conflicts

1. Light (#1, #3, #4, #8–10) and dark (#2, #5–7, V1) references are mixed. V2 shows both themes, so build both, with dark as the default.
2. The card-board style differs: #5 uses dense dark cards with a status footer; #6 adds gate subtitles, a cost line and amber borders. Combine them: #5's layout plus #6's gate subtitle and needs-you styling. Cost is optional.
3. #4 opens task detail in a drawer, while #7/V1 open runs as full tabs. Use the drawer for a quick look and a tab when the task is opened.
4. Not covered by this half: docs editing, chapter-based tours, onboarding/templates, VM config forms. These must come from the other half of the references.
